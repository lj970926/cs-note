# Chat: RL test-time scaling 是什么

> 2026-07-29 Claude Code 会话存档。本文件为原始材料，归档后不再修改。

## Q

RL test-time scaling 这个是啥？

## A

### 两个 "scaling" 的对立

- **Train-time scaling（训练时扩展）**：更多参数、更多数据、更多训练算力，模型一次性变强。GPT-3→GPT-4 时代的主线。
- **Test-time scaling（测试时扩展）**：模型训练好后不动，在推理时花更多算力换更好的答案——让模型"想久一点"。

RL（强化学习）是让"想久一点"真正有效的训练手段，所以两个词常绑在一起。

### RL 在这里干什么

光多生成 token 没用——普通模型想久了只会啰嗦和跑偏。RL 解决的是教会模型如何有效利用额外的推理时间：

1. **可验证奖励（RLVR）**：数学、代码任务有客观对错（答案匹配、测试通过），可自动给奖励，不需要人类标注。
2. 用这些奖励做强化学习，模型自己涌现出长链思维行为：分步推理、自我质疑（"等等，这步对吗"）、回溯重试、多角度验证——DeepSeek-R1 论文里的 "aha moment"。
3. 训练出的模型，思维链越长答案越准——推理时间变成新的可调旋钮。

### 效果

OpenAI o1 发布博客的标志性结果：准确率随 test-time compute 呈对数线性增长——想的时间每翻几倍，AIME 竞赛数学题准确率涨一截；且在 train-time scaling 边际收益递减的地方这条曲线还在涨。

### 两种花算力的姿势

| 方式 | 做法 | 例子 |
|---|---|---|
| Sequential（串行） | 生成更长的思维链，边想边自我修正 | o1、R1 的长 CoT |
| Parallel（并行） | 同时采样多条路径再聚合/筛选 | best-of-N、多数投票（self-consistency）、verifier/PRM 打分搜索 |

RL 主要增强串行线；并行线更多靠过程奖励模型（PRM）或简单投票。

### 为什么重要

它改变了"模型能力"的定义：同一个模型，给 100 token 和 100k token 思考预算是两个能力水平。

- 产品层面：出现"思考预算"档位（low/medium/high reasoning effort）
- 成本层面：贵不贵不只看模型大小，还看让它想多久
- 竞争层面：小模型 + 长思考可以打平大模型 + 短思考（R1 比 GPT-4 小得多但数学更强）

一句话：**RL test-time scaling = 用强化学习教会模型把"更长的思考时间"转化为"更准的答案"，让推理算力成为继参数、数据之后的第三条扩展轴。**
