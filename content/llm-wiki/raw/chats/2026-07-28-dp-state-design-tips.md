# Chat: DP 子问题与状态转移方程的构建技巧

> 2026-07-28 Claude Code 会话存档（[[llm-wiki/raw/chats/2026-07-28-knapsack-counterexample-and-dp|背包与 DP 会话]]的后续）。本文件为原始材料，归档后不再修改。

## Q

DP 的子问题和状态转移方程的构建有哪些技巧？

## A

### 一、状态设计：先回答"子问题是什么"

状态设计的本质是**用一组参数唯一刻画一个子问题**。核心检验标准：**无后效性**——给定状态后，之前怎么到达这个状态不影响后续决策。常用套路：

**1. 从"决策序列的前缀"出发**

大多数 DP 状态都是"处理到第 i 个元素"这类前缀结构：

- 背包：`dp[i][w]` = 前 i 件物品、容量 w
- LIS（最长上升子序列）：`dp[i]` = 以第 i 个元素结尾的最长上升子序列长度
- 编辑距离：`dp[i][j]` = 串 A 前 i 个字符与串 B 前 j 个字符的最小编辑距离

技巧：当一维前缀不够时，看缺什么信息就加一维。背包里"前 i 件"不够——还需要知道剩多少容量，于是加 w 维。

**2. 状态里只放"影响未来"的信息**

问自己：站在当前位置往后看，过去的哪些信息会影响接下来的最优决策？只有这些信息需要进状态。

- 买股票含冷冻期：`dp[i][状态]` 需要记录"今天是否持有/是否在冷冻期"，因为昨天的交易影响今天的合法性。
- 不需要记录"历史上每只股票的买入价"——那不影响未来，进了状态只会让状态爆炸。

**3. 状态值 = 优化目标**

`dp[...]` 存什么？通常就是题目要求的量（最大价值、最少步数、方案数）。如果题目要求的量不满足最优子结构，有时要改存"到达该状态的最优值"。

### 二、转移方程：从"最后一步决策"倒推

转移方程几乎都可以用这个框架推出：

> 问：到达当前状态的最后一步操作是什么？枚举它的所有可能，取最优。

- 背包：最后一步 = 第 i 件物品"拿或不拿" → `max(dp[i-1][w], dp[i-1][w-wᵢ]+vᵢ)`
- 编辑距离：最后一步 = 插入/删除/替换/匹配 → 四个前驱状态取 min + 代价
- 爬楼梯：最后一步 = 迈 1 级还是 2 级 → `dp[i] = dp[i-1] + dp[i-2]`

这个"枚举最后一步"的视角能系统性地避免漏情况——它比"从前向后想我能去哪"更不容易出错，因为前驱集合通常是封闭可枚举的。

### 三、常见的状态设计模式（按题目特征选型）

| 模式 | 状态形态 | 经典问题 |
|---|---|---|
| 线性 DP | `dp[i]` 或 `dp[i][附加维]` | 爬楼梯、打家劫舍、股票系列 |
| 背包型 | `dp[i][容量]` | 0-1/完全/多重背包、子集和 |
| 区间 DP | `dp[i][j]` = 区间 [i,j] 上的最优 | 石子合并、回文相关、戳气球 |
| 双序列 DP | `dp[i][j]` = A 前 i、B 前 j | LCS、编辑距离 |
| 状态压缩 | `dp[i][S]`，S 是 bitmask | TSP、铺砖、小规模的"哪些已选" |
| 树形 DP | `dp[u][...]` = 子树 u 的答案 | 树上独立集、换根 DP |

识别信号：两个字符串/数组对比 → 双序列；答案依赖"区间内部怎么分" → 区间 DP（转移是枚举分割点 k）；约束里 n ≤ 20 → 大概率状压。

### 四、几个实战技巧

**1. 先写暴力递归，再机械地改成 DP**

最稳的路径：回溯/递归暴力 → 发现重复子问题 → 加记忆化 → 再改填表。递归的参数列表往往就是状态，递归返回值的组合方式往往就是转移方程。想不出状态时，先写暴力。

**2. 状态爆炸时：换"状态里存的东西"**

LIS 的 O(n²) → O(n log n)：`dp[i]` = 以 i 结尾的 LIS 长度（枚举前驱），改成 `dp[len]` = 长度为 len 的上升子序列的最小结尾值（二分更新）。同一个问题，状态定义不同，复杂度天差地别。

**3. 决策不满足无后效性时：把"历史影响"折进状态**

打家劫舍首尾成环：抢第一家会影响最后一家。技巧是破环成链、分类讨论（抢第一家/不抢第一家各跑一遍线性 DP），而不是硬把"第一家抢没抢"塞进每个状态（虽然那也行）。

**4. 边界与初始化：转移方程的一半**

- 想清楚 `dp[0]` / 空前缀 / 空区间是什么——"什么都不选"通常价值 0、方案数 1。
- 初始化非法状态为 +∞ / -∞，避免它们被误取进最优。
- 填表顺序必须保证前驱先于当前被计算：背包容量正序还是倒序，取决于"同一件物品能不能重复用"（完全背包正序、0-1 背包倒序，倒序正是为了防止同一件被用两次）。

**5. 求方案数 vs 求最优值：结构同构**

转移方程里 `max/min` 换成 `+` 就是计数 DP；想输出具体方案，就额外记一个 `choice[i][w]` 数组回追。

### 五、验证 checklist

写完一个 DP，按这四条自查：

1. **无后效性**：状态相同 ⇒ 未来最优决策相同？
2. **完备性**：转移枚举了到达该状态的所有可能方式吗？
3. **顺序**：每个前驱都先于当前状态被算出？
4. **边界**：最小子问题的值对吗？非法状态被排除了吗？

一句话总结：**状态设计是"用最少的信息唯一刻画未来"，转移方程是"枚举最后一步决策"，暴力递归是最可靠的脚手架**。
