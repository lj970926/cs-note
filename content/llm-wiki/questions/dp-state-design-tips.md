# DP 状态设计与转移方程技巧

## Question

DP 的子问题和状态转移方程的构建有哪些技巧？

## Answer

### 状态设计：先回答"子问题是什么"

本质：用一组参数唯一刻画一个子问题。核心检验标准是**无后效性**——给定状态后，如何到达它不影响后续决策。三个套路：

1. **从前缀结构出发**：大多数状态是"处理到第 i 个元素"（背包 `dp[i][w]`、LIS `dp[i]`、编辑距离 `dp[i][j]`）。一维不够时，看缺什么信息就加一维。
2. **只放"影响未来"的信息**：站在当前往后看，过去的哪些信息影响接下来的最优决策，只有这些进状态（如股票冷冻期只需记录"是否持有/冷冻中"，不需要历史买入价）。
3. **状态值 = 优化目标**：通常就是题目要求的量；若其不满足最优子结构，改存"到达该状态的最优值"。

### 转移方程：枚举"最后一步决策"

通用框架：**到达当前状态的最后一步操作是什么？枚举所有可能，取最优。**

- 背包：第 i 件拿/不拿 → `max(dp[i-1][w], dp[i-1][w-wᵢ]+vᵢ)`
- 编辑距离：插入/删除/替换/匹配 → 前驱取 min + 代价
- 爬楼梯：迈 1 级或 2 级 → `dp[i] = dp[i-1] + dp[i-2]`

"枚举最后一步"比"从前向后想能去哪"更不易漏情况，因为前驱集合封闭可枚举。

### 模式选型

| 模式 | 状态形态 | 经典问题 | 识别信号 |
|---|---|---|---|
| 线性 DP | `dp[i][附加维]` | 爬楼梯、打家劫舍、股票 | 单序列决策 |
| 背包型 | `dp[i][容量]` | 0-1/完全背包、子集和 | "在限额下选物品" |
| 区间 DP | `dp[i][j]` | 石子合并、戳气球 | 答案依赖区间内部怎么分（枚举分割点 k） |
| 双序列 DP | `dp[i][j]` | LCS、编辑距离 | 两个串/数组对比 |
| 状态压缩 | `dp[i][S]` bitmask | TSP、铺砖 | n ≤ 20 |
| 树形 DP | `dp[u][...]` | 树上独立集、换根 | 子树答案拼父亲 |

### 实战技巧

1. **先写暴力递归再机械化**：递归参数 ≈ 状态，返回值组合 ≈ 转移方程；想不出状态时先写暴力。
2. **状态爆炸就换存的东西**：LIS 从"以 i 结尾的 LIS 长"（O(n²)）换成"长度 len 的最小结尾值"（O(n log n) 二分）。
3. **后效性违规就折进状态或分类讨论**：环形打家劫舍 → 破环成链，"抢/不抢第一家"各跑一遍。
4. **边界与填表顺序是转移方程的一半**：空集通常价值 0/方案数 1；非法态设 ±∞；前驱必须先算（0-1 背包容量倒序防物品复用，完全背包正序）。
5. **计数与最优结构同构**：`max/min` 换成 `+` 即计数 DP；记 `choice[][]` 可回追具体方案。

### 自查 checklist

1. 无后效性：状态相同 ⇒ 未来最优决策相同？
2. 完备性：转移枚举了到达该状态的所有方式？
3. 顺序：每个前驱都先于当前被算出？
4. 边界：最小子问题的值对吗？非法状态被排除了吗？

> 一句话：**状态设计是"用最少的信息唯一刻画未来"，转移方程是"枚举最后一步决策"，暴力递归是最可靠的脚手架。**
